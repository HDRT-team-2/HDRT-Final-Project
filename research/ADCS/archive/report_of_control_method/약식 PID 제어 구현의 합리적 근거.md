# Flask 기반 제어 시스템에서 피드백 루프 생략의 합리적 근거

## 1. 보고 목적  
본 보고서는 Flask를 기반으로 한 전차 제어 시스템 내에서,  
`현재값 → 오차 계산 → 제어출력` 과정을 **코드 내부 루프 없이 수행해도 되는 이유**를 논리적으로 설명한다.  
즉, **“Flask를 활용하고 있기에, 코드 내에서 피드백을 구현할 필요 없이 생성물을 반응물로서 재명명하는 과정을 생략할 수 있다”**는 주장의 합리성을 기술한다.  

---

## 2. 시스템 구조적 관점

| 구분 | Flask 서버 구조 | 전통적 제어 루프 구조 |
|------|------------------|----------------------|
| **작동 방식** | 클라이언트(또는 시뮬레이터)가 주기적으로 서버에 상태값(`angle`, `velocity` 등)을 전송함. Flask는 해당 요청을 받을 때마다 PID 계산 수행 후 결과를 반환함. | 제어 코드 내에서 `while` 루프를 사용하여 오차 계산 → 제어값 생성 → 업데이트를 반복 수행함. |
| **루프 존재 형태** | 코드 내부에는 **반복문이 없으나, 요청-응답 사이클 자체가 반복 구조로 작동**함. | 루프가 코드 레벨에서 직접적으로 존재함. |
| **결론** | Flask의 구조적 특성상, **루프를 명시적으로 작성하지 않아도 피드백 순환이 성립**됨. | 루프가 반드시 코드 내부에 존재해야 피드백이 동작함. |

---

## 3. 제어이론적 관점

PID 제어의 본질은 **폐루프(feedback loop)** 에 있다.
즉, 출력(생성물)이 다시 입력(반응물)으로 순환하며 보정이 이루어진다.

Flask 환경에서는 이 과정이 다음과 같이 자동으로 성립된다.

그렇기에, 굳이 코드 내부에서 (보정값 -> 현재값)으로의 갱신을 통한 루프 형성을 고집하지 않아도 PID 제어를 통한 전차 제어에는 문제가 없다.
